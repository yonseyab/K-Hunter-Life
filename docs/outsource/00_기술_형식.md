# 외주 데이터 — 기술 형식 (Claude 준비분, 2026-10-23)

> **의뢰서가 아니다.** Codex 의뢰서는 만들기 전에 사용자와 상의한다 (CLAUDE.md). 이 문서는 의뢰서에 붙일 **기술 부분**(데이터 형식 · 태그 · `asserts` · 조건 · 검사 규칙 · ID 배치 · 팩 규칙)만 정리한 것이다.
> 스타일은 [`../STYLE_CHECKLIST.md`](../STYLE_CHECKLIST.md) (사용자 확정). ID 목록은 [`ID_참조.md`](ID_참조.md) (`node tools/gen_id_reference.js` 로 다시 만든다).

## 1. 파일 · 등록

- 형식: `def('테이블', [ {…}, … ]);` 만 쓴다. 함수 · 변수 · import 금지.
- 소량(수백 행): `game/data/ext/<테이블>_<배치>.js` → `game/data/ext/_list.js` 에 한 줄.
- 대량: `game/data/packs/<테이블>_<배치>_<세 자리>.js` (파일 하나 500행 안팎) → `game/data/packs/_manifest.js` 의 `HL_PACKS` 에 한 줄. 게임이 타이틀에서 뒤에서 불러온다.
- 납품 뒤 반드시: `node tools/validate_data.js` (없는 ID · 중복 ID · 테이블 규칙 · 같은 문장 · **세 층 원칙**). 오류 목록을 그대로 돌려주면 된다.

## 2. ID · 배치 코드

- 모든 ID 에 배치 코드를 넣는다: `EV_RC00001`, `SL_DA00001`. 대문자 · 숫자 · `_` 만. 번호는 5자리.
- **B 는 Claude 기본분**(최소 재료)이다. 외주는 B 를 쓰지 않는다. 옛 버전 배치(LA · CA · LB · BB · PB · EB · WB · GB · NB · MB · IB · TB · KB · OB)도 다시 쓰지 않는다.
- 기존 행은 고치지 않는다. 다른 데이터를 가리킬 때는 `ID_참조.md` 에 있는 ID만.

## 4. 조건 `req` (이벤트 · 문장 공통)

옛 조건 키는 그대로 (`ID_참조.md` · `docs/outsource/16_커마_발동조건.md` 참고). 새로 생긴 키:

| k | 형식 | 뜻 |
|---|---|---|
| `looks` | `{k:'looks', aspect:'APS_FACE', min:15}` (`who:'tgt'` 가능) | 외모 점수 1~20 (사실, 1층) |
| `emo` | `{k:'emo', id:'EM_ANX', min:30}` | 지금 감정 세기 0~100 |
| `self` | `{k:'self', aspect:'looks'|'skill'|'money'|'belong', max:40}` | 자기 인식 0~100 (3층) |
| `adult` | `{k:'adult'}` | 나와 대상 모두 성인 (`BAL_REL.adultAge`). **성적 내용은 반드시 이 조건** (STYLE 23) |
| `place` | `{k:'place', in:['PT_CAFE']}` | 지금 있는 장소 종류 |
| `money` | `{k:'money', min:…, max:…}` | max 도 쓸 수 있게 됨 |

이벤트 선택지에도 `req` 를 달 수 있다 (조건이 안 맞으면 그 선택지가 안 보인다).

## 5. 세 층 원칙 — `asserts` (검사 도구가 강제)

- **세상은 사실대로 반응하고, 마음은 성격대로 받아들인다.** 이벤트 · 문장이 캐릭터에 대해 무언가를 단정하면(잘생겼다 · 키가 작다 · 가난하다 …) 그 사실을 `asserts` 에 적고, **같은 사실이 `req` 에 반드시 있어야 한다.**
- 같은 종류(`k`) · 같은 대상 키(`aspect` · `item` · `axis` · `id` · `key` · `who`)이고, `req` 범위가 `asserts` 범위 안이어야 통과한다. 예: `asserts:[{k:'looks',aspect:'APS_FACE',min:15}]` 면 `req` 에 `min:15` 이상이 있어야 한다.
- 외모 · 형편을 단정하는 낱말(잘생 · 예쁘 · 미인 · 못생 · 뚱뚱 · 키가 크 · 키가 작 · 부자 · 가난 · 몸매 …)이 문장에 있는데 `asserts` 가 없으면 오류. 다른 인물 이야기라 해당이 없으면 `noAssert:true`.
- 비꼬는 말(사실과 다른 평가)은 **질투하는 특정인**에게서만 (`react:jealous`, 관계 경쟁심 · 원망이 높은 사람). 서술(지문)은 비하에 동조하지 않는다 (STYLE 24).

## 6. 판단 엔진 재료: 선택지 `tags`

- 이벤트 · 위기 선택지에 `tags:['TAG_KIND','TAG_SOCIAL']` 처럼 의미 태그를 붙인다 (`ID_참조.md` › 의미 태그). 점수 = 태그 × (성격 · 감정 · 상태 · 자기 인식 · 방침).
- 위기 선택지는 옛 `style`(safe · careful · bold · greedy · team · escape)만 있어도 태그로 바뀐다. 둘 다 없으면 효과로 추정한다.
- 이벤트에는 `kind`(멈춤 종류 `SK_…`)를 단다 — 사용자가 '어떤 사건에서 멈출지' 고른다. 없으면 추정한다.
- `fx.emo:{EM_JOY:20}` 로 감정을 남길 수 있다.

## 7. 규모 · 진행 (옛 2차 대량 규칙 중 유효한 것)

- 파일 하나 500행 안팎 · 진행 기록 문서(`docs/outsource/진행_<배치>.md`)에 묶음별 완료 행 수 · 마지막 파일 · 마지막 ID · "계속"하면 이어서 · 묶음을 10%씩 돌아가며.
- 같은 문장은 오류 (검사 도구 `checkDupText` — storyLines 는 `on + text` 기준).
- 측정: 이벤트 5만 행에서 불러오기 0.6초 · 메모리 70MB (옛 버전). 10만 행 수준까지 문제없음. 그 이상이면 분류별 지연 로딩을 Claude 가 만든다.
