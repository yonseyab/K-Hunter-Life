# 장소 외주 의뢰 (GPT용, 2026-10-24)

> 사용자 결정 (2026-10-24): 장소는 GPT 외주. 한국 배경 헌터 세계에 있을 만한 것만, 시 · 군 · 구 단위까지, 이름 있는 개별 장소까지. 깊은 세계관 설정은 파고들지 말고 **디폴트값만**. 세부는 나중에.
> 아래 '---' 밑을 그대로 GPT에게 붙여 넣는다. 작업 폴더는 이 저장소(K-Hunter-Life).

---

너는 한국 현대 헌터물 생활 시뮬레이션 게임 **K-Hunter-Life**의 **장소 데이터**를 만드는 기획자야.
코드는 건드리지 말고, 아래에 적은 데이터 파일만 만들어. 다 만든 뒤 `node tools/validate_data.js`를 돌려서 "문제 없음"이 나오게 해 줘.

## 1. 세계 (기본값만 — 새 설정을 만들지 마)

- 지금은 **2026년의 한국**이야. 1999년에 첫 게이트가 열렸고, 사회는 이미 적응했어. 헌터 협회 · 관련 법 · 헌터 보험 · 인증 제도 · 헌터 병원 · 길드가 있어.
- 인구의 0.5%가 각성자이고, 실제로 싸우는 헌터는 0.2%야. 헌터는 스타가 아니라 위험하고 피곤한 현장 노동자에 가까워.
- 헌터와 게이트 등급은 20급(가장 낮음) ~ 1급(가장 높음). 대부분은 20~15급이야.
- 게이트에서 나오는 마정석은 발전 · 산업 에너지원이야. 무소속 헌터는 협회 매입소에 팔아.
- 성좌가 있다는 건 세상이 알고 있어. 성좌 관련 장소는 만들지 마.
- **새 단체 · 새 역사 · 새 사건을 만들지 마.** 협회 · 길드 · 병원 · 공방처럼 일반적인 것만 써. 이 세계에서 바뀐 건 "게이트와 헌터가 생겨서 생긴 시설"이 있다는 정도야.

## 2. 만들 것

### 2-1. 장소 종류 추가 (`placeTypes`)

이미 있는 9개는 고치지 마: `PT_HOME` 집 · `PT_TRAIN` 헌터 훈련장 · `PT_LIB` 도서관 · `PT_CAFE` 카페 · 식당 · `PT_WORK` 일터 · `PT_ASSOC` 협회 지부 · `PT_HOSPITAL` 헌터 병원 · `PT_GUILD` 길드 사무실 · `PT_GATE` 게이트 현장

여기에 **20~35개**를 더해. 한국에 흔한 생활 장소와, 헌터 세계라서 생긴 장소를 섞어서. 예를 들면 이런 것들이야 (그대로 쓰지 않아도 돼).
- 생활: 편의점 · 마트 · 시장 · 헬스장 · 술집 · 찜질방 · 공원 · 학교 · 종교 시설
- 헌터: 헌터 용품점 · 장비 공방 · 마정석 매입소 · 헌터 숙소 · 헌터 전용 바
- 공공 · 교통: 경찰서 · 주민센터 · 역 · 터미널 · 공항
- 자연: 산 · 바닷가 · 강변

```js
def('placeTypes', [
  {id:'PT_STORE', name:'헌터 용품점', icon:'▦', group:'shop', where:'city', sources:['SRC_STORE'], desc:'보급형 장비와 소모품을 파는 가게.'},
]);
```

| 필드 | 규칙 |
|---|---|
| `id` | `PT_` + 영문 대문자 (예: `PT_STORE`). 기존 9개와 겹치지 않게 |
| `name` | 한국어 짧은 이름 |
| `icon` | 글자 하나 (기호나 이모지 아님. 예: ▦ ✚ ♨ ⛰ 같은 단순한 기호 하나) |
| `group` | `life` 생활 · `hunter` 헌터 · `shop` 가게 · `public` 공공 · `move` 교통 · `nature` 자연 · `etc` 기타 |
| `where` | 어디에 있나: `all` 어느 시 · 군 · 구에나 · `city` 시 · 구에만 (군에는 드묾) · `metro` 광역시 · 큰 도시에만 · `rare` 전국에 몇 곳만 |
| `sources` | (선택) 그곳에서 아이템을 구할 수 있으면 아래 ID: `SRC_ASSOC_SHOP` 협회 공식 매장 · `SRC_STORE` 민간 헌터 용품점 · `SRC_ONLINE` 온라인 쇼핑 · `SRC_USED` 중고 거래 · `SRC_WORKSHOP` 공방 주문 제작 · `SRC_GUILD` 길드 · `SRC_ASSOC_GIVE` 협회 지급 · 포상 · `SRC_BLACK` 암시장 |
| `desc` | 한 줄 설명 |

### 2-2. 장소 꼬리표 (`placeTags`)

사건 조건에 쓸 꼬리표를 **20~30개** 만들어. 분위기 · 가격대 · 위험 · 혼잡 · 시간대 같은 것.

```js
def('placeTags', [
  {id:'PTAG_CHEAP', name:'저렴함', desc:'주머니 가벼운 헌터들이 모인다.'},
]);
```

`id`는 `PTAG_` + 영문 대문자.

### 2-3. 이름 있는 개별 장소 (`places`)

**전국 시 · 군 · 구 221곳 모두**에 개별 장소를 만들어. 지역 목록은 `docs/outsource/ID_참조.md`의 지역(RG_) 표나 `game/data/regions_all.js`에 있어.

| 지역 | 곳마다 개수 |
|---|---|
| 서울의 구 · 광역시의 구 | 6~10 |
| 그 밖의 시 | 5~8 |
| 군 | 3~5 |

- 지역마다 **그 지역다운 곳**을 넣어. 유명한 역 · 시장 · 공원 · 산 · 바다처럼 실제로 있는 공공 장소, 그리고 그 동네에 있을 법한 가게 · 시설.
- 헌터 세계 장소(협회 지부 · 헌터 병원 · 훈련장 · 용품점 · 공방 · 매입소)는 지역 크기에 맞게 섞어. 군에는 적게, 큰 도시에는 많게.
- 모든 지역에 같은 장소를 복사해 넣지 마. "○○구 헌터 용품점"처럼 이름만 바꾼 행이 계속 나오면 안 돼.

```js
def('places', [
  {id:'PL_PA00001', name:'망원시장', type:'PT_MARKET', region:'RG_SEOUL_MAPO', desc:'헌터 등록증을 보여 주면 덤을 얹어 주는 집이 몇 곳 있다.', tags:['PTAG_CHEAP','PTAG_CROWDED'], scale:'region', real:true},
  {id:'PL_PA00002', name:'합정 헌터 공방', type:'PT_SMITH', region:'RG_SEOUL_MAPO', desc:'칼날 재연마를 당일에 해 주는 작은 공방.', tags:['PTAG_LOCAL'], scale:'local', real:false},
]);
```

| 필드 | 규칙 |
|---|---|
| `id` | `PL_PA` + 5자리 번호 (`PL_PA00001`부터, 파일이 나뉘어도 번호가 겹치지 않게) |
| `name` | 1~24자 |
| `type` | `placeTypes` ID (기존 9개 또는 2-1에서 만든 것) |
| `region` | 지역 ID (`RG_…`) — 목록에 있는 것만 |
| `desc` | 한 문장, 60자 이내. 그곳의 분위기나 헌터와 엮이는 점 하나 |
| `tags` | `placeTags` ID 0~3개 |
| `scale` | `local` 동네 사람만 앎 · `region` 그 시 · 군 · 구에서 알려짐 · `national` 전국에 알려짐 |
| `real` | 실제 있는 공공 지명(역 · 시장 · 공원 · 산 · 해수욕장 등)을 썼으면 `true`, 지어낸 곳이면 `false` |

### 실존 이름 규칙

- **써도 되는 것:** 실제 지명, 역 · 시장 · 공원 · 산 · 강 · 해수욕장 같은 공공 장소 이름
- **지어내야 하는 것:** 가게 · 회사 · 병원 · 학교 · 호텔 · 프랜차이즈 같은 상호. 실존 상호나 브랜드를 쓰거나 바로 떠올리게 하지 마.
- 실존 장소에 게이트 사건 · 사고 같은 나쁜 역사를 지어 붙이지 마. 분위기와 헌터 생활 정도만.

## 3. 파일 · 등록

- `game/data/ext/placeTypes_PA.js`: 2-1
- `game/data/ext/placeTags_PA.js`: 2-2
- `game/data/ext/places_PA_<시도>.js`: 2-3 (시도별 17개. 예: `places_PA_SEOUL.js`, `places_PA_GYEONGGI.js` — 시도 키는 `regions_all.js`의 `prov`)
- 만든 파일 이름을 모두 `game/data/ext/_list.js`의 `HL_EXT` 목록에 한 줄씩 추가해. 순서는 placeTypes → placeTags → places.
- 형식은 `def('테이블', [ {…}, … ]);`만 써. 함수 · 변수 · import 금지.
- 기존 파일과 기존 행은 고치지 마.
