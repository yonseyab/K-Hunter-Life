# 설계 결정 (K-Hunter-Life) — 지금 유효한 것만

우선순위: **사용자의 최근 말 > 이 문서 > STYLE_CHECKLIST > Claude 임시값**.
2026-10-24 정리: 나중 결정에 덮인 옛 항목 · 끝난 '나중에' 항목은 지웠다 (지난 기록은 GitHub 커밋 기록에). 'Claude 결정'은 사용자가 맡긴 것 — 사용자가 바꾸면 바로 고친다.

## 1. 게임의 뼈대

| 주제 | 결정 |
|---|---|
| 정체성 | 『80억분의 1』의 매우 디테일한 버전. 한국 헌터물 + 성좌물 **관찰형 인생 시뮬레이션** — 커마한 헌터의 인생이 흘러가고, **플레이어는 그 헌터의 성좌**로서 지켜본다 |
| 개입 | 플레이어는 헌터를 직접 조종하지 않는다 (행동 · 이동 · 시간표 · 파티 · 전투 · 장비 착용 · 스탯 분배 없음). 성좌가 하는 것: 지켜보기 · 선물(코인) · 축복 · 헌터가 물어 오면 조언. 따를지 · 입을지 · 쓸지는 헌터가 정한다 |
| 시간 | 하루 30초(×1). 배속 · 일시정지 · 다음 사건까지. 오프라인 진행 없음 |
| 세계 | 2026년 현재 한국 · 1999년 첫 게이트(27년) · 각성 0.5% · 활동 0.2% · 등급 1급(최상) ~ 20급 · 망한 나라 있음 · 날짜 · 지도 · 물가는 2026 그대로 |
| 시작 · 끝 | 커마(또는 전체 무작위) → 각성 직후 · 무소속으로 시작, 각성 전 인생은 짧은 요약. 사망 · 은퇴 → 노년을 짧게 흘리고 일대기 한 장 · 작별 한마디 |
| 이어 가기 | 같은 세계 새 인물 · 플레이 중 인물 바꾸기 · 기록관(시점 · 관계 골라 새 게임) · 파일 |
| 게임 안 AI | 넣지 않는다. 모든 내용은 ID 데이터 + 규칙 |
| 만드는 순서 | 기본 시스템 · 기초 DB(장소 · 아이템 · 몬스터 · 인물)를 먼저, 선택지 · 이벤트는 그 위에. 범죄는 맨 나중 |
| 미뤄 둔 것 | **범죄 · 자녀(다음 인물로 이어 가기와 함께) · 잠재력 '전부 엿보기'(만들어 두고 꺼 둠) · 각성 전 일상부터 시작 · 성좌의 지시** |

## 2. 이야기 · 판단

| 주제 | 결정 |
|---|---|
| 문장 | 상세도 기본 '자세히'(요약 · 보통 가능). 공략은 장면으로 (입장 → 구역 → 위기 → 보스 → 결과). 세상 소식이 섞인다. 스타일은 STYLE_CHECKLIST |
| 개수 | 하루의 일 · 사건 · 만남 · 공략 수를 미리 정하지 않는다. 이야기꾼: 조용하면 살짝 올리고 몰리면 살짝 낮춤 |
| 효과 숫자 | [기력 −12] 같은 숫자를 보이지 않는다 — 문장으로 ('조금 지쳤다.'). 숫자는 엔진 안에서만 (`fxWords`) |
| 판단 엔진 | 하루 일정 · 이벤트 · 위기를 하나의 엔진이. NPC 도 같은 엔진. 태그 × 재료 + 약간의 무작위 + 이유 문장. 경험이 성격을 바꾼다. 내 헌터 주변 · 이야기에 나온 사람은 판단 엔진, 오래 안 엮이면 배경으로 (가까운 사람은 남음). 배경 NPC 는 집계 · 단순 효용 |
| 세 층 원칙 | 사실 · 세상의 반응 · 마음. 단정하는 문장은 조건(req)에 그 사실이 꼭 있어야 한다 (`asserts` + 검사 도구) |
| 감정 | 천천히 바뀌고, 상태 칸에 하나만, 바뀔 때만 한 줄, 일대기에 연 · 월 그래프 |
| 사건 · 위기 | 인생 화면의 카드(모달)로. 헌터가 성좌를 알면 고민될 때 성좌에게 묻고, 성좌가 답하면 따를지는 헌터가 정한다 (신뢰 · 성격 · 상태 · 성향 차이 · 위험 · 호감). 모르면 묻지 않고 혼자 정한다. 주사위 · 판정 숫자는 보이지 않는다 |
| 성좌 신뢰 | 숫자 없이 문장으로만. 단계가 바뀔 때 이야기 창 한 줄, 관계 탭 성좌 칸에 지금 단계 |
| 소식 · 대화 | 별도 편지함 없이 이야기 창에 한 번씩. 이벤트 · 길드 계약 제안은 카드로 |
| 인생 기록 | 인생 창은 현재 달만. 지난달은 IndexedDB 에 월별로, 일대기에서 '지난 일생 돌아보기'(연 · 월 · 날짜 · 종류 · 검색) |

## 3. 성좌

| 주제 | 결정 |
|---|---|
| 성좌 = 계정 = 세이브 칸 | 기본 3칸. 업적 · 코인 · 해금이 성좌에 쌓이고 헌터가 죽어도 남는다. 한 번 받은 업적은 다시 못 받는다. 성좌 하나는 헌터 한 명만 (죽거나 은퇴해야 새 헌터). **한 번 만든 성좌는 고칠 수 없다** (지우고 새로) |
| 새 게임 흐름 | 성좌 고르기/만들기 → (새 성좌면) 성좌 인트로 5장면 → '정해진 성좌로 깨어나기' / '나만의 성좌 빚기' → 헌터 인트로 → 커마 → 시작 전 확인 → 플레이. 인트로는 글자만 |
| 나만의 성좌 | 이름(자동 생성) · 성향 · 영역/상징 · 색 · 문양 · 말투. 시작 코인은 늘 0. 헌터는 처음엔 성좌를 모르고 일상 중 무작위로 알아챈다 |
| 정해진 성좌 | **사용자가 만든다** (`starPresets` — 구조 · 고르기 화면 · 시작 때 고유 클래스/스킬 지급 · 업적 잠금은 준비됨). 자기 성향에 맞는 메시지 · 지시만 |
| 세계관 | 세상은 성좌가 있다는 걸 안다 (누가 어느 성좌인지는 모름). 헌터 한 명에 성좌 하나, 성좌 하나가 여럿을 키울 수 있다. NPC 성좌가 다른 헌터를 후원하고 경매에서 경쟁 |
| 코인 | 내 헌터가 몬스터를 잡으면 쌓인다 + 업적. 상점 · 성좌 경매장 · 축복 · 잠재력 엿보기에 쓴다 |
| 선물 | 산 물건은 바로 헌터 가방으로. 헌터가 성좌를 알면 "성좌 ○○가 선물했다", 모르면 **운이나 노력으로 얻은 것처럼** (`giftCovers`) |
| 상점 · 경매장 | 성좌 상점(매일 진열이 바뀜, 헌터 등급에 맞는 물건 위주 + 상시 물건) · 성좌 코인 경매장 하나. 헌터가 현실 가게 · 경매에서 사는 사건은 나중에 |
| 고유 클래스 | 선천 각성으로는 못 얻는다. 성좌가 주거나 고유 클래스북으로만. 성좌 하나에 하나, 가진 헌터는 세계에 한 명. 받으면 원래 클래스가 바뀐다 |
| 업적 · 해금 | 업적을 이루면 코인. 해금: 클래스 · 능력치 · 잠재력 직접 고르기, 잠재력 엿보기 무료 (다음 헌터를 만들 때 적용) |
| 잠재력 보기 | 성좌의 힘: 기본은 이야기 문장(성장의 벽 등)으로만 짐작. 코인 · 업적으로 '대략 엿보기'. '전부 엿보기'는 미룸 (`BAL_STAR.peekFull`) |
| 메시지 · 축복 | 메시지는 정해진 때(선물 · 레벨 · 등급 · 공략 · 부상 · 알아챔 · 사망 …)마다 성향에 맞는 한 줄. 축복은 코인으로 거는 일시 효과 (판정 · 전투 보정). 둘 다 데이터만 채우면 돈다 |

## 4. 헌터 · 커마 · 성장

| 주제 | 결정 |
|---|---|
| 커마 | **잠재력 · 클래스 · 능력치는 무작위**(각성 결과), 클래스 · 능력치는 '다시 굴리기' 무제한. 업적 해금으로 직접 고르기. 특성은 포인트로 고르기. 커마 선택은 능력치 효과가 아니라 사건 · 대사의 발동 조건 (외모 점수만 조금 영향 — `lookScoreFx`) |
| 스탯 포인트 | 헌터가 스스로 나눈다 — 클래스 성향 · 역할 · 성격 · 처진 스탯 메우기 (`BAL_STATALLOC`), 이유는 이야기 창 한 줄. 성좌에게 묻는 순간은 선택지 · 이벤트 단계에서 |
| 클래스 | 이름은 헌터 소설풍 (전사 · 검사 · 버서커 · 성기사 · 흑마법사 · 검성 …). 계열(classCats 6) × 역할(roles 7). 처음 각성 = 1차 · 고유 아님, 희귀도 높을수록 드묾. 클래스당 스킬 = 각성 후보 6(그중 2개) + 기본 패시브 1 + 레벨 습득 3 |
| 스킬 | 소속(클래스 · 공용 · 고유 · 몬스터) × 종류(액티브 · 패시브) × 효과 영역(전투 · 탐색 · 생활 · 사회). 공용 스킬은 skillCats 묶음. 이름 분위기는 희귀도로 (1~2 시스템 게임풍 · 3~4 한자 무협 · 5 · 고유 웹소설 칭호) |
| 전투 | 실시간 통계 시뮬 (0.5초 단위 HP · 딜). 내 헌터 · 상세 인물이 낀 공략에. 배경 인구끼리는 성공률 표. 5구역 게이트 약 2시간 |
| 게이트 · 몬스터 | 게이트 하나 = 잡몹 1~3종 + 보스 1. 몬스터 등급은 범위. 특별한 게이트는 분류(kind)만 — 지금은 브레이크 |
| 승급 | 상태창이 판단해 자동 승급, 강등 없음 |
| 기본 규칙 (옛 버전에서) | 판정 = 능력 + d20 ≥ 난이도 (자동 성공 · 실패 없음) · 기본 스탯 4(신체 · 정신 · 마력 · 감각) + 세부 능력(각성자 전문 30 · 공통 40 · 비각성자 20) · 분 단위 시간 + 기력 · 수면 부족 · 훈련 수확 체감 · 관계 8차원 · 외모 1~20 + 개인 취향 (성인만 성적 평가) · 특성 최대 5개 · 길드 설립 · 장소 · 이동 · 아는 것 vs 사실 · 전국 230 지역 · 게이트 이름 = 실제 장소 |

## 5. 아이템

| 주제 | 결정 |
|---|---|
| 등급 | 일반 · 고급 · 희귀 · 영웅 · 전설 + 숨은 '신화'. 기본 보정 +1 · +2 · +4 · +7 · +11 · +16. 등급이 성능 · 개성 칸 · 내구 · 구하는 곳 · 사회 반응을 정한다 (헌터 등급별 보통 장비는 보편일 뿐) |
| 착용 | 등급 · 스탯과 상관없이 누구나. 칸: 무기 · 보조(양손이면 같이) · 상의 · 하의(한 벌이면 같이) · 귀 · 목 · 손 · 특수. 장비 성능(stat)이 전투 능력치에 더해진다 |
| 개성 | 아이템마다 0~3개(`itemTraits`), 좋은 개성엔 단점을 같이 |
| 내구도 | 쓰면 닳고, 헌터가 알아서 공방에 수리 맡김 |
| 출처 | 13가지 (협회 매장 · 용품점 · 온라인 · 중고 · 공방 · 경매장 · 드롭 · 길드 · 협회 지급 · 상점 · 사람 · 암시장(틀만) · 직접 제작) |
| 마정석 · 소재 | 마정석 = 게이트 등급 × 품질 4단계, 협회 판매 · 사회 에너지원. 소재 = 몬스터 계열 × 부위 ('마철'이라는 말은 쓰지 않음) |
| 미룬 것 | 제작 · 강화 (넣지 않음) · 등급 안 품질 단계 · 생활품 · 귀속 · 클래스 전용 같은 특수 조건 |

## 6. 화면

| 주제 | 결정 |
|---|---|
| 좌측 메뉴 | **이야기**(인생 · 일대기) · **내 헌터**(정보 · 상태창 · 관계) · **성좌**(내 정보 · 상점 · 성좌 경매장 · 업적) · **DB**(맨 아래). 옛 화면(게이트 · 길드 · 재정 · 뉴스 · 전국 현황 …)은 링크로만 — 어디에 둘지 사용자와 정할 일 |
| 인생 화면 | 가운데 넓은 이야기 창 · 오른쪽 위 작은 상태창(EXP 아래는 접기) · 그 아래 위젯(자금 · 즐겨찾기 인물 최대 10 등). 코인은 상단 '각성한 지 ○일째' 왼쪽. 게이트 안이면 상태창이 붉게 |
| 정보 탭 | FM 정보창 느낌으로 촘촘하게: 이름 띠 + 핵심 칸(등급 · 레벨 · 클래스 · 역할 · 소속 · 기본 스탯 4개 …), 사진은 왼쪽 줄 맨 위 따로, 긴 내용(각성 전의 삶)은 접기. 조작 버튼 없음 |
| 상태창 | 기본 상태 · 장비(착용 칸 · 내구도 · 더해지는 값) · 클래스/스킬 · 특성 |
| 관계 탭 | 헌터가 사람들(그리고 성좌)을 어떻게 생각하는지만 (상대 마음은 안 보임). 마음마다 다른 말 5단계 + 눈금 10칸 막대. '형/오빠' · '누나/언니'는 헌터 성별에 맞춰 하나만 |
| DB | 시뮬을 보며 '이게 뭔지' 확인하는 곳. 탭 8개(인물 · 게이트 · 몬스터 · 장비 · 장소 · 기타 · 클래스 · 스킬), 검색 · 정렬 · 사용자가 고르는 분류 칩. 상세는 한 줄 요약 → 시뮬에서 실제로 하는 일 → 분위기 글. 클래스 상세는 '이 클래스로 얻을 수 있는 스킬' |
| 설정 | 재생(물어 올 때 · 물어 올 일 · 상세도 · 배속) · 화면(글자 크기 · 인트로 · 자동 저장) · 헌터 관리(헌터 사진 주문서 · 은퇴) · 개발. 판단 방침 · 공략 속도 같은 옛 설정은 없앰 |
| 헌터 사진 주문서 | 커마 외형 전부를 이미지 AI 프롬프트로 (실사 · 심플한 흰 배경 · 장식 없음) |
| 새 헌터 만들기 | 오른쪽 초상화 에셋 칸 없음. 의상 선택지는 짧은 취향 문구. 성격 요약은 짧은 이름 + 한 문단 (256가지) |
