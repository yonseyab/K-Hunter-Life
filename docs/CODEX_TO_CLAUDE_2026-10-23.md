## 2. 게임 방향 전환

시뮬레이션이 주체다. 플레이어는 방향/목표, 중요 사건의 선택, 구매/장비 관리 등에 개입한다. 세부 행동을 하나씩 고르거나 직접 이동·일정 편집·파티 편성·수동 공략을 진행하는 구조는 일반 플레이에서 막았다.

- `game/engine/observe.js`: 기존 직접 조작 UI 정리와 실행 경로 차단. 내부 엔진/기존 화면은 필요한 범위에서 유지한다.
- 방향 선택을 GOALS → ROUTINE → SIM 자동 일정에 연결했다.
- 소식/대화는 인생 로그로 전달한다. 내부 alerts/threads 데이터 자체를 삭제한 것은 아니다.
- 공략 위기는 자동 공략 도중 선택하고 다시 자동 진행한다. `G.play.pendingRaid`로 대기를 저장/복원한다.
- 하루는 ×1 기준 30초다. 배속/일시정지/다음 사건 기능을 유지한다.

## 4. 상태창과 스탯 분배

- 홈 상태창은 기존 상태 항목을 따른다. 클래스/스킬/특성은 버튼을 눌러 펼치는 대신 이름을 텍스트로 표시한다.
- 내 헌터 → 상태창의 내부 탭: **기본 상태 / 클래스 · 스킬 / 특성**.
- 클래스 · 스킬에서는 클래스 박스 아래에 스킬 박스를 배치한다.
- 기본 상태에서 스탯 분배안을 만들면 현재/적용 후 수치와 실제 계산식에 따른 HP/MP 등의 예상 변화를 확인한다. 적용 전 실제 포인트와 스탯을 바꾸지 않는다.
- 취소/초과 분배/중복 적용을 방지하고, 인물·저장·기반 수치가 바뀌면 오래된 분배안을 초기화한다.
- 세부 능력은 향후 삭제 예정이므로 새 상세 UI에서 제외했다. 엔진 전체 삭제는 하지 않았다. 부상/상태 이상은 기존 기능을 유지한다.
- 주요 파일: `game/engine/hunter_status.js`, `game/hunter_status.css`, `game/engine/status_ui.js`.

## 6. 게이트 표시와 선택 팝업/주사위

- 게이트 진입 시 별도 안내 배너를 끼워 넣지 않는다. **상태창 색상을 붉게 바꾸고 제목줄에 게이트 안/외부 연락 및 다른 행동 불가를 표시**한다. 진입/퇴장 시 아래 칸이 밀리지 않게 높이를 유지한다.
- 직접 선택할 사건/공략 위기/계약/회고는 하단 추가 칸 대신 native `dialog#lifeEventModal`로 표시한다.
- 실제 d20 판정 결과를 한 번 적용하고 애니메이션으로 공개한다. 장식용 숫자에 게임 난수를 소비하지 않는다. 무판정 선택은 바로 처리한다.
- 주사위 팝업 설정: 이번 애니메이션만 스킵 / 항상 애니메이션 스킵하고 결과 즉시 공개 / 항상 인물에게 맡기기.
- 지속 설정은 **인물별** `G.player.choicePrefs={skipDice,delegate}`에 저장한다. 인물을 바꾸면 분리되고 돌아오면 복원된다. 설정 → 재생·멈춤에서도 해제할 수 있다.
- 항상 맡기기는 기존 EVT/MIND/AUTORAID로 판단한다. 결과를 무조건 성공시키는 설정이 아니다.
- 주요 파일: `game/engine/life_ui.js`, `game/engine/play.js`, `game/engine/story.js`, `game/life.css`.

## 7. 월별 인생 원문 보관과 일대기

- 인생 창은 현재 달 기록만 활성 표시한다. 과거 원문을 900줄 초과 시 삭제하던 처리를 제거했다.
- 지난달 원문은 IndexedDB **`khl-life-log` / `months`**에 UUID 키의 불변 묶음으로 보관한다.
- `G.story`는 현재 달 전체 원문이다. 화면은 최근 300~500줄을 표시하되 “이번 달 전체 보기”로 나머지도 읽는다.
- `G.storyArchive={v,months,pending}`는 월별 묶음 참조/메타데이터와 쓰기 대기 원문을 보관한다. IDB 쓰기 완료 전에는 pending을 세이브에 남겨 저장 실패 시 복구한다.
- 과거 세이브가 미래 분기의 기록을 참조하지 않게 했다. 저장 슬롯 삭제 시 기록 DB를 자동 삭제하지 않는다.
- 일대기 → **지난 일생 돌아보기** 팝업에서 연/월/날짜/종류 필터, 월별 및 전체 기간 검색, 검색 결과의 해당 날짜 이동, 최근 기록, 페이지 이동을 제공한다.
- 100건 단위 표시, 필요한 달만 읽기, 최대 3개월 캐시, 취소 가능한 검색으로 100년 이상 기록에 대응했다.
- 주요 파일: `game/engine/life_log.js`, `game/engine/history_ui.js`, `game/history.css`, `game/engine/story.js`.
- 주의: 이미 옛 버전에서 삭제된 원문은 복원하지 못한다. **기존 헌터 JSON 내보내기에는 월별 IndexedDB 원문이 포함되지 않는다.** 로컬 브라우저 기록과 내보낸 JSON을 동일한 백업이라고 취급하지 말 것.

## 8. 새 헌터 만들기: 최신 정정까지 반영된 상태

### 외형/의상과 긴 선택지

- 의상 스타일은 기본 10개 + 확장 50개 = **60개 전체**를 짧은 취향 문구로 통일했다.
- 예: `캐주얼한 옷차림 선호`, `몸의 선이 드러나는 옷 선호`, `품이 넉넉한 옷 선호`.
- 사용자는 `슬림 이너 레이어드` 같은 옷 종류/기술적인 조합 이름을 원한 것이 아니다. 앞서 단어형 이름으로 바꾼 단계는 최신 정정으로 대체됐다.
- ID/저장값은 유지했다. 확장 50개의 기존 문장은 desc에 보존하며 툴팁과 검색에서 사용한다.
- 기본 정보/외형/출신 배경 공통 선택지, 왼쪽 선택값, 상단 현재값은 말줄임 대신 줄바꿈과 자동 높이를 적용한다. 320px 화면까지 검사했다.
- 주요 파일: `game/data/look_options.js`, `game/data/ext/lookOpts_LA.js`, `game/data/ext/lookOpts_LB.js`, `game/index.html`의 공통 CH 선택 UI/CSS.

### 성격 요약

- **최종 표시 = 짧은 요약명 + 바로 아래 짧은 설명 한 문단**이다. 긴 세부 설명 목록만 제거했다. 짧은 설명까지 지우면 안 된다.
- `persRoles` 16종 × `persStyles` 16종으로 **256개 고유 요약명**을 만든다. 예: `활달한 조력자`.
- 8개 슬라이더 극성을 반영하는 결정적 규칙이다. 표시를 위해 게임 난수를 쓰거나 슬라이더 값을 바꾸지 않는다. 미정/중간 성향은 별도 완화 처리한다.
- 짧은 설명은 각 규칙의 desc를 조합하며 슬라이더 입력에 맞춰 갱신한다. 생성 단계와 최종 확인 화면에 모두 표시한다.
- `buildHunter`가 저장하는 personality는 여전히 요약명이다. 실제 판단은 기존 8개 축 수치를 사용한다. 슬라이더 아래 단계별 예시는 유지했다.
- 길게 붙던 상세 묘사용 persExtra/persCombos/persNeutral/persFacets 및 strong/mid/view/stress/hunter/balanced 데이터는 제거했다. `game/data/ext/pers_PB.js`도 삭제하고 `_list.js`에서 제외했다.
- 주요 파일: `game/data/personality.js`, `game/index.html`의 `persHeadline`/`persSummaryHTML`/`pxUpdate`, `game/engine/validate.js`, `tools/gen_id_reference.js`.
- ID 참조 문서 `docs/outsource/ID_참조.md`를 재생성했다.

## 10. 이어받을 때 주의할 점

1. 현재 로컬 파일을 기준으로 이어갈 것. 오래된 저장소/아티팩트 파일로 덮어쓰지 말 것.
2. UI는 사용자 합의 배치와 원본 로그를 유지할 것. 추가 장식/제목/큰 여백을 임의로 넣지 말 것.
3. “짧은 성격 설명 복원”과 “의상 60개 취향 문구”가 마지막 사용자 정정이다.
4. 세부 능력 엔진 전체 삭제, 새 빈 탭의 내용 구현, 월별 원문 JSON 백업은 완료된 작업으로 간주하지 말 것.
5. 게임 내 LLM 없이 ID 데이터와 규칙으로 동작하는 기존 원칙을 유지할 것.
6. 새 작업 내용은 사용자의 다음 지시로 정한다. 이 인계 자체가 새 기능 구현 요청은 아니다.
