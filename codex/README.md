## 모든 의뢰에 공통으로 지킬 것

### 1. 게임 한 줄 소개
한국 헌터물 + 성좌물 **관찰형** 인생 시뮬레이션이다. 2026년, 첫 게이트가 열린 지 27년(1999년). 플레이어는 한 헌터의 **성좌**로서 그 사람의 인생을 지켜보고, 코인으로 선물하고, 가끔 말을 건다. 헌터는 플레이어가 조종하지 않고 스스로 판단한다.
게임 안에 AI(LLM)는 없다. 모든 문장과 판단은 **ID 기반 데이터 + 규칙**으로 만든다. 그래서 데이터의 양과 질이 곧 게임의 깊이다.

### 2. 작업 장소 · 권한
- GitHub 저장소 `yonseyab/K-Hunter-Life` 의 `main` 브랜치, 그리고 사용자 PC 폴더 `C:\Users\YON\Desktop\K-Hunter-Life` (같은 내용).
- 둘 다 수정 권한이 있다. 작업이 끝나면 **커밋 · push 하고, PC 폴더도 같은 상태로** 맞춘다.

### 3. 손대도 되는 곳 · 안 되는 곳
- **새 데이터 파일:** `game/data/ext/` 에 의뢰서가 정한 이름으로 만든다.
- **목록 등록:** `game/data/ext/_list.js` 의 `HL_EXT` 배열에 파일 이름을 한 줄씩 넣는다 (넣어야 게임이 읽는다).
- **보고:** 이 폴더(`codex/`)의 해당 의뢰서 맨 아래 '완료 보고' 칸.
- **그 밖의 파일은 고치지 않는다.** `game/engine/` · `game/index.html` · 기존 `game/data/*.js` · `tests/` · `docs/` 는 읽기만. 형식이 이상하거나 막히는 점이 있으면 고치지 말고 완료 보고에 적는다.
- 기존 ID를 바꾸거나 지우지 않는다.

### 4. ID 규칙
- `<접두사>_<배치 글자><번호>`. **Codex 배치 글자는 `C`** (B는 Claude 기본분).
- 번호 자리 수 · 범위는 의뢰서마다 정해 준다. 한 번 쓴 ID는 다시 쓰지 않는다.

### 5. 데이터 형식의 기준
- 각 `game/data/*.js` **파일 맨 위 주석**이 형식의 기준이다. 의뢰서는 그중 무엇을 채울지 · 비울지를 정한다.
- 파일 모양: `def('테이블', [ {…}, {…} ]);` — 기존 파일들과 같다. 키는 따옴표 없이, 문자열은 작은따옴표.
- **비울 항목은 키 자체를 쓰지 않는다** (`null` · 빈 문자열 · 빈 배열도 넣지 않는다).

### 6. 문장 스타일
- `docs/STYLE_CHECKLIST.md` 를 따른다. 요약: 3인칭 · 현재형("~한다") · 짧게 끊기 · 건조한 기록체 · 과장 없는 현실적인 긴장감 · 생활감.
- 세계관 고정 사실: **치유 포션은 없다.** 마정석은 에너지원이다. 헌터는 '위험하고 피곤한 현장 노동자'다. 같은 클래스라도 사람마다 스킬이 다르다.
- 실존 인물 · 실존 상표 · 저작권 있는 작품의 고유 명칭(유명 웹소설 · 게임의 스킬명 등)을 쓰지 않는다.

### 7. 검사 (반영 전 필수)
```
node tools/validate_data.js
```
'문제 없음' 이 나와야 한다. 그 다음 UI 테스트(가능하면):
```
CHROMIUM=<크로미움 경로> OUT=<임시 폴더> node tests/ui/run_all.js
```
UI 테스트를 돌릴 수 없는 환경이면 완료 보고에 그렇게 적는다.
