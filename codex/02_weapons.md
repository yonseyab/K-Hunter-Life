# 02 · 클래스별 무기 · 매개체 · 작업 도구

2026-10-24 사용자 요청: 클래스별로 어울리는 무기 명칭을 다양하게 100개씩 만든다. 후속 요청으로 이름뿐 아니라 성능 전체를 포함한 실제 장비 데이터로 확장했다.

## 범위와 형식

- 클래스 **115개**(Claude 기본 7 + Codex 108)에 각 **100개**, 장비 총 **11,500개**.
- 파일 `game/data/ext/codex_weapons.js`. `HL_EXT`에서 `codex_classes.js` 다음에 등록한다.
- `items`: `IT_C00001`~`IT_C11500`. 이름만 담은 목록이 아니라 실제 아이템 행이다.
- `itemTraits`: `ITR_C001`~`ITR_C030`. 신체/정신/마력/감각/근접·무기 판정에 양·음 보정 1~3을 주는 개성이다.
- `classWeaponPools`: `WNP_C001`~`WNP_C115`, `{id, name, cls, items:[아이템 ID 100개], src}`. 클래스별 추천·검색용 연결표다. 아이템에 전용 제한 `cls` · `cond` · `req`는 넣지 않는다.
- 지원·생산 클래스는 해당 직무의 매개체와 휴대 작업 도구를 사용한다. 한손 보조 도구, 양손 주 장비, 변형사의 손 장비를 구별한다.

## 명칭과 성능

- 클래스별로 장비 형태 10개 · 직무 특징 10개 · 별칭 소재 10개를 작성하고 보급/표면 가공/현장 용도/공방 조정/별칭의 여러 표현으로 구성했다. 전체 이름 11,500개가 서로 다르며 숫자나 등급명만 붙여 이름을 늘리지 않았다.
- 클래스별 100개의 `grade/stat/traits/slot/hands` 성능 구성도 서로 다르다.
- 클래스마다 일반 **55**, 고급 **25**, 희귀 **12**, 영웅 **5**, 전설 **2**, 신화 **1**개다. 이는 카탈로그 수량이며 드롭 확률을 뜻하지 않는다.
- 총계: 일반 6,325 · 고급 2,875 · 희귀 1,380 · 영웅 575 · 전설 230 · 신화 115.
- 개성 수/크기는 기존 `itemGrades.traits/mag` 범위에 맞춘다. 영웅 이상에는 실제 음수 판정 개성을 함께 넣는다. 고급·희귀의 단일 양수 개성에는 파지·진동·조절 순서의 부담을 설명에 명시한다.
- 가격은 등급별 임시 기준에 구조와 형태 차이를 반영한다. 코인은 기존 `BAL_COIN.wonPerCoin`을 사용한다. 기존 경제 밸런스 값은 수정하지 않는다.
- 공격형은 공격/마력과 조준을, 방호형은 방어·저항을, 지원·생산 도구는 마력·정밀도와 해당 스탯 개성을 중심으로 설계한다.

채운 항목: 이름 · 영문명 · 분류 · 등급 · 희귀도 · 설명 · 세계관 설명 · 무기/도구 갈래 · 세부 수치 · 거리 · 손 수 · 장착 칸 · 가격 · 코인 · 출처 · 제작 연도 · 출처 문장 · 꼬리표 · 무게감 · 소음 · 은신 보정 · 합법 여부 · 되팔기 · 단품 수량 · 취급 교육 · 획득/장착/파손 문장 · 작성자. 해당 장비에는 양손 점유 · 개성 · 속성 · 저항 · 상태 부여도 넣는다. 실제 능동 사용 효과가 없는 장비에 소비 아이템용 `use`는 넣지 않는다.

## 현재 엔진 적용과 Claude 인계

- `GEAR`의 등급 기본 보정, 주 무기/보조 칸 공략 전력, 양손 점유, 자동 장비 비교, 내구·파손·수리와 가격을 사용한다.
- 개성 `kind:'stat'`의 기본 스탯 묶음 판정과 `kind:'check'`의 근접·무기 판정은 연결되어 있다. 파손 시 개성 보정도 사라지는지 확인한다.
- 최대 내구·마모·수리 배율은 새 아이템 키를 만들지 않고 기존 등급 정의를 참조한다. 신화는 기존 규칙대로 닳지 않으며, 기존 경매의 숨은 등급 제외 조건을 따른다.
- 개별 `stat.atk/mag/def/res/spd/acc/eva/crit`, 장비 `el/se/resist`, 무게감·소음·은신은 형식에 맞춘 설계 데이터다. 현 엔진은 이를 개별 전투 계산에 모두 적용하지 않는다. 특히 일반 등급 55개의 기본 공략 보정은 같고 세부 수치 차이가 현재 전력에 직접 더해지는 것은 아니다.
- 개성의 설명상 파지·진동 부담은 새 행동/기력 비용을 자동 추가하지 않는다. 음수 개성의 판정 손실은 현재 적용된다. 전투 통합 때 세부 수치와 등급 보정의 중복 가산을 검토해야 한다.
- `classWeaponPools`는 추천표다. 현재 `GEAR.consider`는 클래스 적합성보다 등급과 개성 합계를 비교하므로 추천표를 읽는 판단은 별도 연결이 필요하다.
- 경매는 현재 숨은 신화를 제외한 아이템에서 고른다. 출처별 공급 빈도와 희귀도 가중치를 이 데이터만으로 완전히 통제하지 않는다.
- **기존 엔진 문제:** `GEAR.power()`는 주 무기와 보조 칸을 각각 조회할 때 같은 인벤토리 행을 다른 래퍼 객체로 만든다. `s !== w`가 참이 되어 양손 장비의 전력을 한 번 더 절반 가산한다. 중복된 인벤토리 행 기준으로 비교해야 한다. 변경 없는 `main`(`10da063`)에서 메모리에만 만든 IG_1 양손 장비로 기대 전력 0.1 → 실제 0.15(1.5배)를 재현했다. 같은 인벤토리 행이지만 래퍼 객체가 다름도 확인했다.
- 같은 객체 비교 문제는 `GEAR.consider()`의 `Set`에도 있어 현재 양손 장비의 점수를 두 번 합칠 수 있다. 양손 장비를 교체할 때 함께 검토한다. 이 의뢰에서는 엔진 파일을 수정하지 않는다.
- 파일 크기는 약 **15.4 MB**다. 전체 로드와 DB·경매·저장 흐름을 검사한다. 지연 로드나 팩 전환은 엔진 담당 범위다.
